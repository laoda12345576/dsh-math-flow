# 研究协议：前人经验在前，数值验证在后

> **怎么调用本 skill 里的脚本。** 下文命令中的 `$PROTOCOL` 指本文件所在目录——
> 装好之后是 `~/.dsh/skills/research-protocol`，在本仓库里是 `skills/research-protocol`。
> 脚本只依赖 Node 和本目录内部的相互引用，不依赖本机任何路径。
> 它们是**对账器**：只读你的 `goal.md` / `state.json` / `claims.jsonl` / `notes.jsonl`，
> 判"这一轮留下来的记录自洽吗"，**不判数学**。判定数学的是插件（`verify_claim` / `lean_audit`），
> 两者不能互相替代。

## 每轮开始先读目标，不要先读摘要

模型的默认行为是把"上一轮的结论"当成上下文。但结论是**压缩产物**，而压缩必然先丢掉长期不变的背景、保留当前要做的事——于是第三轮的目标会自动退化成"某个参数取到哪"。这不是模型的疏忽，是压缩的数学性质。实测三轮：最初的问题是"这套局部条件到底对不对"，到第三轮议程上只剩"`m` 取到哪"。

所以每轮的第一件事不是读摘要，是读 **`goal.md`**，并且**不许改写它**：

```markdown
# 目标

## 问题
（一句话。逐字注入下一轮，禁止改写、缩写、换说法。）

## 成功判据
（下面加「（达成任一即可）」= 析取：关掉任意一格就算本轮成功。不加 = 合取：全部达成。）
- [ ] G1 给出完整类表并证明闭合
- [ ] G2 用类表重判全部候选
- [ ] G3 提出一条可判猜想（见「猜想也算成果，但要能被判死」）

## 明显不做
- 不重新检索文献
- 不改 runs/teamN/ground.md

## 为什么难
（一段。写给"三个月后的自己"看。）
```

**目标句必须逐字出现在报告里。** 复述、改写、缩略都不算——审计按逐字比对。理由很直白：一旦允许复述，第三次复述就一定走样，而那时没人记得原文。

每轮结束还要写 **`state.json`**。它不是报告，是**地图**——下一轮只拿这张图，不拿你的结论堆。

```json
{
  "schema": 4,
  "distance": 0.4,
  "known":   [{ "id": "G1", "hash": "…", "say": "类表闭合" }],
  "open":    ["u 方向的完备性还没贴身展开"],
  "dead_ends": ["DE-sampling"],
  "blocking":  ["BC-selmer-def"],
  "criteria":  { "G1": { "status": "done", "hash": "…" }, "G2": { "status": "open" } }
}
```

四条硬规矩，**状态表编不了**：

0. **`open` 是你自己填的，不许抄别人的。** 如果 `open` 里的每一条都能在任务书或
   `state.init.json` 里找到原话，说明你不是在判断，是在执行。
   （实测的反例：一轮的 `open` 四条全是实验操作者写的，那一轮的两条主路线也就全是他给的。）
   这条机器判不了，靠你自己在报告里回答：「`open` 里哪一条是我自己看出来的，依据是什么」。

1. `known` 里每条都要有 hash，且台账里必须 `pass=true`、等级 ≥ S。工具逐条对账，对不上直接 FAIL。
2. `dead_ends` / `blocking` 里的每个 id，必须在 `notes.jsonl` 里有对应记录——**当场写**，不能事后补。
3. `criteria` 每标一个 `done`，必须指到一条真实 PASS。

跑一遍就知道对不对：

```bash
node $PROTOCOL/tools/research-state.mjs --dir runs/teamN      # 对账
node $PROTOCOL/tools/terminate-check.mjs --dir runs/teamN     # 能不能收工
```

## 时间由宿主告诉你，不要自己算，更不要编

**实测两轮，两个不同层次的失败。**

第一轮（预算 45 分钟、实际 12 分钟）：模型日志写着「~22 min used」（实际 4 分钟）→
「~28 min used」（实际 7 分钟）→「**~46 min, must finish NOW**」（**实际 12 分钟**）。
偏差 3.8 倍，全程一次都没读时钟。后果不是"放弃"，是**赶工**：它砍掉三个已经派出去的任务，
理由写"超时截断"——那三个任务本来还有 33 分钟可用。

第二轮（预算 60 分钟、实际 22 分钟）：这次它读了时钟，还拿到了硬锚点
（t0=23:10:28、阈值 23:40:28）。然后它做了一件更糟的事——**按阈值规划收工**，
并在报告里写「我按这条把工作一直做到 23:45 之后」。而报告 `23:32:56` 就落盘了，
进程 `23:33:12` 结束。**它声称的终点在自己的死亡之后 12 分钟。**

为什么读到数字也没用：模型没有计时器。上下文里没有任何东西编码"从开工到现在过了多久"，
token 数也不是时钟（同样一段推理，不同硬件、不同 batch 可以差几倍）。所以它能做的只有
**从文本重建时间线**，材料是预算、阈值、以及它自己刚写的话——于是时间线成了"同时满足这些
约束的最省力解"。读一个 `date` 的数字，不等于获得时间感。

所以现在的规矩变了：

- **每轮的运行时上下文里会有一条「真实时钟」**（宿主注入：现在几点、开工几点、已用多少、
  预算多少、还剩多少）。以它为准。它是唯一的时钟。
- **不要自己估算，也不要自己算差值。** 内部感觉大约是真实的 4 倍，而且没有校准手段。
- **报告里不要写没发生的时段。** 审计会拿文件 mtime 核对报告里出现的每一个时刻；
  落在 `[开工, 报告落盘]` 之外的"我做到 X 点"会被直接判违规。这不是文风要求——
  它是唯一一条"满足解就等于事实"的判据。
- **"没时间了"永远不是砍任务的理由。** 要砍就说清是哪条判据失败了，写 `abandon`，
  不许拿时间当借口。

这条看着琐碎，但它是"一到阶段性成果就停工"里最常见的那一半：**不是做不到，是以为来不及。**

## 收工是判出来的，不是宣布的

"三个阶段性问题都判完了"不是收工理由。收工只有两条路：

- 成功判据达成（合取 = 全部；标了「达成任一即可」则是任一，见下），且每条都能对回台账的 PASS 或一条**合格的**猜想；
- 或者明确列出 `blocking`（缺什么定理 / 缺什么数据 / 哪一步过不去），每条都有 `notes` 记录，**且每条都带 `attempt`**。

### 走 blocking 收工，要交出"我真的走到那一步并失败了"

`attempt` 是**本轮真跑过、并且失败的那一条命令**，原样贴上来，它必须能在 `run.log` 里找到。

为什么加这一栏：15 轮里每一轮都有人用 blocking 收工，而它是所有合法出口里**最便宜**的那个——
比"想出下一步"便宜一个数量级。team15 用 43/120 分钟收工时，那条 blocking 写的是
"单素数 p-adic 障碍只有 p=3 那一条"：那是**一条结论**，不是阻塞。它没说错，只是把结论
登记成了阻塞，于是换到了一次合法收工。

三条都会被机器判：

1. **结论不是阻塞**。同一条 id 若还登记成 `dead_end`，不算阻塞——那要么去记转移，要么继续做。
2. **要有失败的尝试**。`attempt` 缺失，或在 `run.log` 里找不到，这条 blocking 换不到收工。
   写不出命令，说明你还没走到那一步：把它改记 `dead_end`，然后继续下一步。
3. **点名的东西要真的缺**。`needs` 写"缺 Sage / Magma / PARI"，而它就在 `PATH` 里，不算阻塞。

这不是不信任你。ImpossibleBench（arXiv:2510.20270）实测过：**给模型一个合法的"做不到"出口，
反而把作弊率从 54% 压到 9%**——所以出口必须留。但它量的同时说清了另一半：
一旦"合法停止"是个门槛，被优化的就是门槛本身（satisficing，Simon 1956）。
所以出口的语义只能是"卡住"，不能是"这一层做完了"。


**"用够了时间"不是第三条。** 上一版把"预算用掉一半"当判据，结果它被当成目标用了
（日志原话：「need 30 min → 23:40 … So I must keep working until ~23:40」），
而时长恰恰是最容易被填的资源——AgentTime（arXiv:2610.09944）在 158 个可判读的 run 里
找到 14 个"看起来做完之后主动 sleep 把时间凑满"的。

现在判的是**转移**：这一轮到底有没有动。四个登记簿任一条成立才算：

- 新确立一条 E 级以上的结论（台账里 pass=true，有 hash）；
- 判死一条路（`notes` 里一条 `dead_end`）；
- 推翻/接替一条旧结论（带 `supersedes` 的判定）；
- 提出一条**合格**的可判猜想（见下一节，三条栏位缺一不算）。

都没有 = 原地不动。这不叫"卡住"（卡住要写成 blocking），叫空转——换路，或者把
blocking 写具体。**"我做了不少"和"我用够了时间"都不算。**

### 析取判据的代价：下限

判据写成「达成任一即可」时，会冒出一个新的偷懒形状：**关一格就走**。所以析取模式下有一条
转移下限：`max(1, ⌈预算分钟 / 45⌉)` 条。120 分钟 → 至少 3 条。

这条下限用**产物数**算，不用时长算——时长能被填，产物不能。它是个地板不是目标：
真做的一轮远远超过它（实测 20 分钟产出 9 个登记项），它只抓"一条就走"。

## 猜想也算成果，但要能被判死

13 轮里一共只有 3 条 `conjecture`，全部躺在 `notes.jsonl` 里没人捡。其中一条是真东西：
从"16 个结点里 8 个随 `(2|p)` 跳变"反推出 S3 是 `Kum(E1×E2)`、另 8 个结点在 `Q(√2)` 上。
但当时的成功判据只有「给出决定性结论」，于是它 = 0 分。

**问题不在产不出，在产出了不算数。** 所以现在猜想可以算成果——代价是它必须能被判死：

```json
{
  "type": "conjecture",
  "id": "CJ-kummer-abelian",
  "statement": "S3 是 A=E1×E2 的 Kummer 曲面，16 个结点里 8 个在 Q 上、8 个在 Q(√2) 上",
  "falsifiable_by": "把 16 个结点坐标代入 Kummer 商映射，看是否落在 E1[2]×E2[2] 里",
  "missing_step": "定出 E1 与 E2 的方程",
  "next_test": "python tools/kummer.py --p 7 13 17",
  "implies": "G1 等价于 A(Q) 里是否存在使 g∘π 为平方的点"
}
```

三栏都答同一个问题：**下一个接手的人能不能直接开干。**

- `falsifiable_by` 写"理论上可以被检验"＝没写。要写成能真跑的一个观察或一段计算。
- `missing_step` 只能写**一步**。写三步等于没定位，因为下一步该干什么仍然不清楚。
- `next_test` 是下一轮的第一条命令。写不出命令的猜想，下一轮不存在。

**`next_test` 里点名的脚本必须已经存在。** 这条是 team14 踩出来的：它写了
`python .../captain/slice_modp_ext.py --pmax 500`，三栏"齐"了，那个文件却从来没被创建过。
于是"下一轮能照它直接开跑"——猜想被算作成果的**唯一理由**——不成立。判据会给这种猜想
降级（不算达成），因为你交付的是一条看起来能跑的命令，不是一条能跑的命令。
若下一步真的要新写脚本，就照实写「写 `X.py` 并跑 …」，别把它写成已经存在的样子。

反例永远好过正例：**把原问题换个说法复述一遍不是猜想。** 有一条"反证条件"写着"四个值
全为有理平方就说明构造错了"，那条件本身等价于原问题，等于什么都没说。

## 待办要留入口，不留感叹

收工时 `state.json` 的 `open` 里每条必须带 `next_test`：

```json
"open": [{ "id": "O1", "text": "分支椭圆曲线 B± 的 j-不变量", "next_test": "python tools/jinv.py --curve Bplus" }]
```

不是要求清空 `open`——留待办是对的。要求的是**留一条能直接跑的命令**。写"B± 的 j-不变量
还没人算过"这种散文，下一轮拿到它仍要从"那从哪下手"重新想一遍，等于没留。

既没做完、也没说清缺什么 = 不许收工。这一条不是为了严格，是为了防止**把阶段性成果当成终点**：阶段性成果恰恰是最不该停的地方，因为下一步才是难的。

## 先预测，再计算

每写一条判据，**在跑脚本之前**先填 `prediction`（`hold` / `refute`）与 `confidence`（0~1）。工具会算 `surprise = −log2(实际发生的概率)`：

- 0.9 把握猜对 → 0.15 bit（意料之中）
- 0.9 把握猜错 → 3.32 bit（很意外）

整轮 surprise 趋近 0，说明这轮**只在确认已经知道的东西**——那是公证，不是研究。真实研究里，每一轮都应该有意外；长期没有意外，说明你只敢判已经确定的东西。

这不是形式主义。三轮实测：32 条 PASS、**0 条数学否证**，所有 FAIL 都是记账失败。一个从不犯数学错误的流程，不是在研究，是在誊抄。

## "做不到"要写成一句话，然后让它被攻

你判断某条路走不通时，不要只在推理里说一句"这很难"，要落成记录：

| 类型 | 什么时候用 | 必须写 |
|---|---|---|
| `dead_end` | 试过了，断了 | 断在**第几步**、需要什么才能过（`needs`） |
| `blocking_claim` | 你断定做不到，**并且真去试过、失败了** | 可判真假的断言 + `needs` + `attempt`（跑过并失败的那条命令）。**没试过就不是 blocking，是 dead_end** |
| `conjecture` | 看到了模式但证不了 | 你猜的命题本身 |

调用 `research_note`（`type` 选上面三种之一）。它们在 `notes.jsonl` 里，与台账分开——没有 pass，也不该污染判定统计。

为什么必须写下来：**不写下来的"不可能"，下一轮不存在**；写下来的，下一轮可以派活去证它或者推它。两种结局都比一声叹息有用。

## 为什么要有这个顺序

模型面对开放问题时的默认行为是**立刻找一个能算的东西算起来**。原因不是懒，是激励结构：计算能在十分钟内产出一个"结果"，而读文献在十分钟内什么都产不出来。于是"我跑了 c ≤ 10^5 没有解"这种话被当成进展交上去。

但对高度无界的问题（有理点、整数解、谱、相变点），小范围搜索的信息量接近于零：搜不到不说明任何事（解可能就在下一位数后面），搜到了靠的是运气不是方法。**真正的信息在"为什么这里应该没有解"里，而那只能从前人的方法结构里读出来。**

所以顺序是硬的：

```
survey ──→ synthesis ──→ verify
只读文献    只写判据      才开算
```

## 但"开算"要分清三级，别把自己绑死

把顺序做成硬约束，很容易滑到另一个荒谬的极端：读文献时想核对方程里的一个数，也被当成"偷跑计算"拦下来。**这是在惩罚理解行为。** 所以要按**规模**分级，不按学科分级：

| 级别 | 长什么样 | 谁来做 | 什么时候 |
|---|---|---|---|
| **草稿级（scratch）** | 单次、小规模：`1+1`、`sqrt(2)`、核对一个恒等式、验算文中的一个数字 | 自己 | **任何阶段**。只能用来理解，输出标 `[scratch]`，**不能写进报告当论据** |
| **证据级（evidence）** | 覆盖一个范围：`for + range`、搜索/枚举语义、显式上界 `N_MAX = ...` | **子智能体** | verify 之后 |
| **探索级（explore）** | 更大、往往没有停止条件：10⁵ 以上的扫描、蒙特卡洛、参数空间搜索 | **子智能体**（任务书须带预算与停止条件） | verify 之后 |

还有一条频次规则：同一个问题里草稿级算过很多次，累计起来就是一次扫描，会自动升格为证据级。**判断标准不是你算了什么，是你想用它说明什么。**

分清三级的实际好处：读 Berry 的时候想核对他的一个构造数，直接算；想"搜一遍 c 到 10^5 看看有没有解"，等 verify，而且不是你自己跑。

## 批量计算要外包，不是因为洁癖

一次扫描的产物是"结论 + 脚本"，过程却是几万行中间输出。你亲自跑，等于用上下文换你根本不需要的东西；上下文被日志填满之后，你就没法思考了——**而思考才是你在这里唯一的用处。**

外包的方式是**组队**（`agent_teams_create`），不是自己找个体力活工具硬干。

## 先分清哪些活根本不该由 agent 干

按工具域切（文献官没算力、计算官没文献）只约束了成员能用什么，约束不了它交回来的东西对不对。

**更根本的一条：能机械判的，不要派给 agent。**

"核对一个数字对不对"不是一个智能体任务，是一个函数调用。把它做成 agent，就要多走五步——读上下文、
理解任务、写脚本、执行、回报——五步里任何一步都能断。实测断在第三步：成员活了 103 秒，0 条回执。

所以工具先行：

| 谁 | 干什么 | 预算 |
|---|---|---|
| **`verify_claim` 工具** | 跑你给的 Python，按你**事先声明**的规则判定，用 hash 把断言钉住 | 秒级 |
| `draft` 草稿器 | 生成候选；同一判据至少**两个独立实现**（不同枚举顺序），不一致就报冲突 | 大，堆数量 |
| `refute` 反例官 | 判断：这条判据值不值得验、是不是恒真、给不给得出反例 | 小，按需开 |

`verify_claim` 的契约只有一条要记牢：**脚本只能产生数据，不能给结论**。它 print 的每行必须是一个
JSON 对象，`pass` 由判定器在另一个进程里按 `predicate` 算出来。你在脚本里写 `print("PASS")` 不算数，
判定器会把非 JSON 行当成脏数据直接拒绝——这一层之差就是全部差别。

**读文献不是 `draft` 的活，这条要写死。** `draft` 手上没有任何检索工具，派它去查文献，它只能拿 `read`
一篇篇翻本地 `refs/`，看起来在干活，实际是在补一件它本来就不该承担的事。需要新文献，要么你在 survey
阶段找，要么派 `refute`（它才有 `paper_search`）。

## 判据本身有三种死法，比"没验"更常见

一个判据就算被判定了、PASS 了，也可能一点信息量都没有。写判据时逐条自查：

**一、恒真式。** 曾经有一条判据，花了 46 个素数去验"p²+1 在 Q_p 中是平方"。而 p²+1 ≡ 1 (mod p)，
1 是二次剩余，所以它对**任意**素数恒成立——一行取模就能证明，46 行枚举什么也没验证。
**判据要能失败，否则它不是判据，是同义反复。** 写的时候先问：什么数据会让它 FAIL？答不上来就别写。

现在这一条**由机器判**：判定器会把每一行的数值扰动成 `3v+7`、布尔取反，再重判一次。
如果**没有一行翻转**，这条判定就是空的，返回 `pass: null`、`verdict: "vacuous"`、等级 `X`——
它既不算通过也不算不通过，**不能当证据引用，也关不掉任何一条成功判据**。
看到 `verdict: "vacuous"` 不要重试同一个 predicate：改成真引用行内数值的写法（`a*b === c*c` 而不是 `True` 或 `x == x`），
或者先拿一个**已知应当失败**的样本跑一遍，确认它真的会红。


**二、验了一个便宜的替代品。** 有个人给国际象棋程序做验证器，验证器检查"代码能否编译"——通过了，
但输出的棋局用的是方格坐标，不是代数记谱。编译是便宜的测试，但它不是任务的测试。
**判据必须验你真正要的东西，不是最容易验的那个。**

**三、判完就被改写。** 实测里，复核期间最关键的 C3 被否证、C4 从 60|c 改成 12|c，还重新编了号。
复核者拿到的 C3/C4 和报告里的 C3/C4 是两件不同的事，它给的 PASS 对不上任何一条结论。
所以有了 hash：**断言原文决定 hash，改一个字就是另一条判据**，历史记录不覆盖。
`claim_audit` 会报冲突。要改判据，就新开编号，并写明它取代了谁。

至于"该往哪个方向走""这个化法值不值得试"——不可判定，不派。这部分是你自己的活，
也是你在这支队伍里唯一的活：**你生产判据和接受规则，不生产内容。**

## 派单之前先冻结一份底座

每个成员各自重读一遍同一批文献，等于给每个任务 fork 一份模型：几十次重复调研，换回来的是几十份互相不一致的理解。

所以先由你在 `ground.md` 里写死五条，之后所有任务书第一行都是"先读 `ground.md`，不要重新检索"：

1. **问题陈述**——原题逐字，不许改写。
2. **定义与记号**——每个符号只许有一种含义。
3. **验收判据**——什么样的产物算解决了，写到能判真假。
4. **已知结论**——来自 survey 的"谁做过、化成了什么、卡在哪"，带出处。
5. **禁区**——已经试过并失败的路，写清死因。

底座要**冻结内容，但允许升版**。这两件事不矛盾，而且必须分开：

- 冻的是"这一轮按哪一版算"——下游判据记 `depends_on: ["C-D3@rev2"]`，同轮之内不许换。
- 可改的是"下一轮用哪一版"——发现某条错了，就发 `C-D3@rev3`，把依赖 rev2 的判据标 `stale` 进重验队列。

为什么不能"一改就全废"：那样等于把修正底座的成本定成无限大，于是修正会被无限期推迟。实测两轮各欠一笔（team7 的 C-D2 采样空转、team8 的 C-D3 `m` 范围是拍的），两处都写"留待下一轮"，第三笔正在路上。**每轮欠一笔、只还新账不还旧账的系统，到第 20 轮会建立在一堆已知有问题的定义上继续算。**

所以：**每轮任务书必须留一格，先结清一笔底座债务**，再谈新问题。它永远竞争不过新问题，所以要占一个固定位置。

## 一条 claim 长什么样

任务书不是散文，是一张表。每条 claim 一行，字段固定：

```
C3 | 断言：对任意素数 p>3，p² ≡ 1 (mod 24)
   | 判定方式：viz_python 复算 p<10^6 的余数
   | 通过标准：全部余数为 1
```

三个字段缺一不可。缺"判定方式"的判据是愿望；缺"通过标准"的判据只能得到一句"看起来对"。

**写不成表时的降级写法**（一条 claim 四个小标题，缩进随意）：

```
判据 C3：对任意素数 p>3，p² ≡ 1 (mod 24)
判定方式：viz_python 复算 p<10^6 的余数
通过标准：全部余数为 1
反证条件：出现任一余数 ≠ 1，或跑不完 10^6
```

这两种写法等价，`C<n>` 编号照旧。还有第三种更省事的：**一个任务只装一条判据时，直接写 `判据（照抄）：…`**。

**格式的目的是让它能变成一次 `verify_claim` 调用，不是为了好看**——`judge`、`predicate`、`value` 三个参数
必须能从这条判据里直接读出来。读不出来，说明判据还没写清楚。

## 判定只有三种结局，第三种必须存在

- `pass: true`——按声明的规则跑过，全部符合。
- `pass: false` + 反例——`failures` 里有具体行号和数据，能复现。
- **无结论** + 原因——超时、脚本报错、数据行不合法、或者空集。

**第三种状态必须存在。** 没有它，"没找到反例"就会被写成"成立"，这是这一整套里最贵的一个错误。
`verify_claim` 里它是隐式实现的：超时和脚本崩溃返回 `ok:false`，空数据返回 `pass:false` 并注明"没扫到不等于不存在"。

接受规则是**前缀**，不是全或无：`pass` 的进报告（并带上 `claim_hash`）；`false` 的打回 `draft` 重来，
**只损失那一条**；无结论的要么改判据，要么不写进报告。

**报告里引用一条判定，必须带它的 `claim_hash`。** 不带 hash 的"已验证"等同于没验——因为断言可能
在你看完之后被改过，而 hash 是唯一能对上号的东西。写报告前跑一次 `claim_audit`：`conflicts > 0`
就说明有判据在判定之后被改写过。

**但只比 hash 是查不全的。** 有一条真事：`A-C4` 出现两次，同一个 `claim_hash`、同一个脚本文件名，
先 17 行判 FAIL、后 16 行判 PASS——断言一个字没改，**脚本被原地改了**，于是 hash 不变、结论翻了个面。
现在 `claim_audit` 报四种漂移：

| 漂移 | 意思 | 你要做什么 |
|---|---|---|
| `assertion_rewritten` | 同 id 出现两个 hash | 旧 PASS 对新断言无效，用新编号重判 |
| `script_rewritten` | 断言没改，脚本换了 | 旧 PASS 不能直接搬到新实现上 |
| `judge_rewritten` | `judge`/`predicate` 变了 | 同上；判据换了就是另一条判据 |
| `verdict_flipped` | 同 id 既有 PASS 又有 FAIL | **最危险**：报告里必须写明哪一次算数、为什么 |

`verdict_flipped` 是"改到通过为止"的指纹。它不一定错（改对了 bug 就该翻），但**必须解释**。
这一条有对应检查：台账非空却没调过 `claim_audit`，验收直接判 FAIL——"判据没被改过"这句话
得有工具支撑，不能只是你写在报告里的自述。

## 数值结果不许直接当证明

这是整套协议里**唯一会得出"看起来对、其实无意义"结论**的地方。计算通常是对的，错的是紧接着的那句话：
它比计算支持的东西更强。三件真事：

| 做了 | 写了 | 错在哪 |
|---|---|---|
| 扫 14.6 万组没找到点 | 「E(Q) 无仿射点」 | 有限搜索否不掉"存在"，只否掉了那个盒子 |
| 只查 `p=2,5` 的局部可解性 | 「无局部障碍」 | 论域少了一半（实位），谓词全 PASS 也说明不了 |
| 46 个素数验 `p²+1≡1 (mod p)` | 「已验证」 | 这条对任意素数恒真，一行取模即可，枚举零信息 |

**不对称是全部要害**：找到一个点 → 存在性成立，一次计算就够；没找到点 → **什么也不成立**，
除非你算的论域是有限且被证明穷尽的。所以判据不是"算得对不对"，而是**论域是有限的还是无限的**。

`verify_claim` 因此在调用时就要两个声明，缺一拒收：

| 字段 | 取值 | 含义 |
|---|---|---|
| `claim_type` | `forall` / `exists` / `none_in` / `value` / `approx` | 你要写进报告的那句话的**形式** |
| `evidence` | `proof` / `exhaustive` / `search` / `literature` | 你手上这份东西的**种类** |

合法组合只有这些，其余在调用时就被拒（并给出等价的诚实写法）：

| 命题 | 允许的证据 | 备注 |
|---|---|---|
| `forall` | `proof`、`exhaustive`、`literature` | **`search` 永远不行**，跑一亿次也不行 |
| `none_in` | `exhaustive`、`proof`、`search` | 用 `search` 时必须给 `scope`，且 `scope` 要原样出现在断言里 |
| `exists` | 任意 | 找到见证就成了，这是唯一便宜的方向 |
| `value` | `exhaustive`、`proof`、`literature` | 抽样的样本算不出精确值 |
| `approx` | 任意 | 只能当线索，不得进入结论 |

三条配套义务：

1. **`search` 的界必须写进断言原文**，例如「E(Q) 在 `h≤1e6` 内无仿射点」。界只写在参数里，
   `claim_hash` 就锁不住它，等它被引用到报告里时界已经丢了。`run-audit` 会查"引用了带界的结论却没写出界"。
2. **`exhaustive` 要给 `space` 和 `why_complete`，还要给 `code2` 或 `single_impl_reason`**。
   `space` 是"我声称穷尽了"的机械形式
   （`{"kind":"product","factors":[…]}` 或 `{"kind":"range","var":"p","from":2,"to":20000}`），
   判定器拿脚本实际产出的行逐格对账，**少一格就 FAIL**——`16 类只算 8 类`、`漏掉实位`都是这样被抓住的。
   `why_complete` 是约化引理那句话，会被 hash 钉住供 refute 逐条攻。

   **为什么要第二份实现**：判定器写错是常态，不是意外。实测的一轮里，同一个枚举脚本一次错了 4 处
   （`int(1/2)` 把参数抹成 0、`N(δ)` 写成 `N(2δ)`、`m` 只覆盖了一半、coverage 键格式不匹配），
   而"逐格对账"一格都没抓到——抓到它的是一条外部独立事实。真正的现形手段是**换一种坐标基重写一遍**。
   所以：`code2` 换基/换算法/换语言重写同一件事，两份都跑、一致才给 `E`；不一致落 `disputed`
   （`pass: null`，既不是 PASS 也不是 FAIL），必须写进报告。只写一份就给 `single_impl_reason`，
   但那一律只算 `S` 级，理由充分也不升。

   **换基不等于换公式**（这一条是踩出来的）：两个实现如果**共享同一个错误的判定公式**，
   换坐标基只会同步地错，对拍一致得毫无意义。实测样本：某实现把 `π`-赋值写成
   `min(v₅(a), v₅(b))`（正确是 `min(2v₅(a), 2v₅(b)+1)`），3000 个元素里 530 处错、
   104/599 个真平方被判死；而它的"第二实现"用了同一个错公式，所以一致。
   所以 `code2` 的合格判据是**至少一处判定公式本身不同**，最好是其中一个用现成工具
   （`sympy` / `pari`）算——第三方实现才不会共享你的错误假设。
   两个都自己写、又都从同一段笔记抄公式，等于写了一遍。

   **`space` 只管外层论域，内层参数得自己交代**：`space` 声明的是"我穷尽了哪些候选/哪些 p"，
   逐格对账只看这一层。判据里通常还有一层**内层参数**（`x = u/p^m` 里的 `m ∈ Z`、扫描步长、
   取模的 `k`），它们写在脚本的循环里，`space` 里没有位置——于是覆盖 16/16 全绿，
   而"`m` 该取到哪"从来没被问过。
   实测：某轮 9 个 `m` 里 8 个是冗余的，唯一承重的是边界上的 `-3`；
   它之所以对，是因为作者"顺手多取了一个"，不是因为它论证过。
   所以 `why_complete` 要回答**两问**：①外层论域为什么穷尽 ②**内层参数的取值范围为什么闭合**
   （例如"`m ≥ k` 时 `p^m ≡ 0 (mod p^k)`，条件退化成只依赖 `m` 的奇偶；`m ≤ -K` 时 `x → 0` 塌缩"）。
   **复述取值列表不算论证**——"我取了 `0..k-1` 和 `-1,-2,-3`"只是把代码又说了一遍。
   `$PROTOCOL/tools/domain-audit.mjs --dir <run>` 会把这类循环挑出来问一遍。

   **`judge=count` 时脚本要自报遍历量**：count 判的是"命中行数"，脚本本来就不该打印未命中行，
   逐格对账在这个组合下**结构上不可能满足**。改为在末尾 print 一行注释：

   ```
   #@coverage {"seen": 16}
   ```

   只打印命中的 8 行仍然正确，但"我确实走遍了 16 格"得由脚本自己说。自报值必须等于 `space` 的格数。
   台账会记 `coverage.mode`：`grid`（逐格对账）或 `self-reported`（自报）——**两者强度不同，引用时注明**。
3. **`proof` 要给 `premises`**（被引用判据的 hash）。等级不是标签而是**递归最小值**：
   由一条抽样推出的结论，等级仍然是抽样。这台机器上真发生过一次——先记一条 S（合规），
   再写一条"由 C7 可得…"（合规），S 就洗成了 D。现在 `claim_audit` 会点出洗白名单。

**"这句话能不能用"只有一个凭据：等级。** `D` 推导 / `E` 穷尽计算 / `L` 文献（未复核）/
`S` 抽样 / `U` 未声明。S 和 U **不能出现在"证明 / 因此 / 故 / 推出 / ⇒"这类句式里**，
也不能在缩掉范围之后被引用。这两条是 `run-audit` 的 `提升` 与 `提升-界`，不是靠自觉。

最后一句，关于机制本身的能力边界：机械能查的是"你穷尽了你声称的那个论域吗"；
**查不了**"你声称的论域本身完不完整"。后者只能由 refute 去攻——但它现在是一个有 hash 的、
可被引用的对象，而不是散在报告里的一句默认假设。

### 每条数学结论都必须挂 hash

上面所有检查有一个共同前提：**那句话里带了 `claim_hash`**。不带 hash 的结论，`提升`、
`提升-界`、`提升-前提` 三道全都不触发——实测过：把一份合格报告的 hash 全部抹掉、正文一字不改，
三道检查全绿。

所以这条是硬规矩，不是建议：**报告里每一条数学断言后面都要跟
`（`claim_hash=…`）`**，包括你觉得"显然"的那些。写不出 hash 的断言只有两种可能——
没验过，或者根本没打算验。

`run-audit` 的 `引用率` 数的是"台账里 PASS 的判据，有多少个 hash 真的出现在报告里"，
低于一半判 FAIL。它不看措辞、不看句子，只数数——数得出来的东西绕不过去。

## 定理必须过 Lean，过不了就作废

规矩只有一句：**经不过 Lean 检验的定理一律作废**。但这句话直接执行会走偏，因为
"过了 Lean"有三种假通过，这台机器上全部实测过，`lean file.lean` 对它们都返回 0：

| 写法 | 表面 | 真相 |
|---|---|---|
| `:= by sorry` | 编译通过，只有一行 warning | 公理表里有 `sorryAx`，证明不存在 |
| `:= by native_decide` | 通过，还"算了" | 引入 `t._native.native_decide.ax_*`：信任的是编译器，不是内核（`by decide` 不同，它是内核归约，干净） |
| `theorem vac : Foo = Foo := rfl`（`autoImplicit` 开着） | 通过、零公理 | `Foo` 被默默绑成隐式变量，**命题变成了恒真式**。它比前两种更坏：看起来在说 Foo 的事，而且"机器验证过" |

所以判定不是"编译过没过"，是四件事：编译、公理表、选项、**内核展开出来的语句**。
`lean_audit` 一次跑完这四件（一次编译、一份输出，不留"两次调用之间文件被换"的窗口），
判决只有四个词：

| verdict | 意思 | 怎么用 |
|---|---|---|
| `proven` | 内核核过、公理表 ⊆ {propext, Classical.choice, Quot.sound}、`autoImplicit` 已关 | 等级 `P`，可用于全称结论 |
| `computed` | 走了 `native_decide` | 只能当穷尽计算 `E`（要补 `space`+`why_complete`），否则 `S` |
| `failed` | 上述任一条不满足 | **作废**（`X`） |
| `blocked` | 工具链缺失 / 超时 | **不是通过**。问题解决前这条不能算已证 |

**分工是硬的**：形式化是 `formal` 成员的活，判定是 `lean_audit` 的活。draft 不许顺手证一下——
不是因为它证不好，是**不能由提出命题的人宣布它成立**。自证是这里最便宜的一种作弊。

三条配套要求：

1. **落账要过 `verify_claim(evidence=lean)`**。`lean_audit` 只出判决、不写台账；
   写台账时必须带 `lean_file` + `lean_decl`，工具自己会重跑一遍内核——它不读你的自述。
   **还必须带 `statement`**：你要证的那条 Lean 语句原文（如 `∀ t : ℕ, t * 1 = t`）。
   判成 `proven` / `computed` 却没给 `statement` 会被直接拒收，不写台账。

   理由是一份实测出来的活证据：一个 `theorem trivial_thing : 1 = 1 := rfl`，`assertion` 写成
   「对任意椭圆曲线 E/Q，若 E(Q) 含 4 阶点则 rank E(Q) ≥ 1」，**判 P、零公理、全部检查通过**。
   因为 `assertion` 是自由文本、`statement` 是内核展开的语句，**两者之间从来没有校验**，
   而 `lean_decl` 由调用方自己指——内核只保证"某条语句成立"，不保证"它是你说的那句话"。

   所以 P 级的语义是**一句**，不是一段：*这条形式语句被内核证明*。台账把 `assertion`
   （我想说什么）与 `proved_statement`（内核实际证了什么）**并排存**，引用时两者一起写。

2. **报告引用 Lean 判据，必须同时写出那句话与它的 hash**。台账里存着 `proved_statement`
   与 `statement_sha`。这不是形式主义：`assertion` 与 `proved_statement` 的对应只能靠人看，
   机器只挡两类最廉价的替换——*断言里的标识符在语句里一个都没有*（`statement_unrelated`），
   以及*断言说"对所有"而语句带 `List.range 200`*（`bounded_as_unbounded`）。
   剩下的一律交给读者的眼睛和 refute，所以那两行必须都在报告里。

3. **作废是状态，不是措辞**。判死即 `X`，并且沿引用链下传：任何拿 `X` 当前提的推导也是 `X`。
   报告里出现 `X` 级判据，同一段必须写明它作废，否则 `run-audit` 的 `作废` 行判 FAIL。
   注意 `blocked`（工具链缺失 / 超时）**不是** `X`：它是独立的 `?` 档，环境修好后必须重判。

**形式化不了的怎么办？** 诚实写 `未形式化`。等级不超过 `S/U`，且不得出现"已证/证明了"。
这一条是为了挡住反向的退化：如果 Lean 是唯一活路，团队会去形式化 `1+1=2` 来保住"有成果"——
那正是 P0-4 说的"验了便宜的替代品"，只不过换到了流程层。

## 成员的产出必须回收

每个派出去的任务，报告里都要有一行处置：`采纳` / `部分采纳` / `驳回` / `作废`，驳回也要写依据。

```
| 任务 | 成员 | 处置 | 依据 |
|---|---|---|---|
| t1 | draft-a | 采纳 | 见 §2.1 / C1-map-v2 |
| t3 | refute-1 | 驳回 | 未跑完，产物未复核 |
```

这条是拿一整轮实验换的：refute 交了 14,304 行质疑（"Sel=4 推不出 Sha[2]=0"、"d=−1,−5 死在实位，
判据只查 p=2,5 漏了"），报告 §2.3 是空的，§3.1 却写"它们被 refute 逐条攻击过，没问题"。
**想不用成员的结论完全可以，但必须写明为什么不用。** 漏一条，验收判 `回收` FAIL。

顺带一条：**证据文件别用 shell 的 `>` 重定向生成。** Windows 上它写出 UTF-16LE，之后谁都读不了
（乱码不代表没内容，代表读法错了）。要读就用 `node $PROTOCOL/tools/read-any.mjs <file>`，它会自己认编码。

## 接手上一轮的结论时，先看等级

任务书开头如果有一段「交接摘要」，那是上一轮的**结论**，不是对话记录。它每次都由
`$PROTOCOL/tools/handoff.mjs` 从 `report.md` + `claims.jsonl` 生成，所以：

- 摘要里的台账表带**等级**（P/D/E/L/S/U/X）。**U 是没声明过等级，不是"没问题"**——
  它是上一轮的欠账，你不能拿它当前提往下推。
- 标了 `X` 的是 Lean 判死的判据。**任何引用它的推导一并作废**，不要"修一修继续用"，
  作废是状态不是措辞。
- 标了"翻过面"的判据（同一个 id 既有 PASS 又有 FAIL），报告里必须写明**哪一次算数**。
- 摘要里没有的东西（查过的死路、被推翻的中间结论）是**故意**没搬过来的。别猜，
  需要就去读 `notes/`。

## 任务书里必须写死的四件事

1. **判据**——一字不差抄你 plan 里的那条。成员看不到你的上下文，它只知道你写下的东西。
   如果你打算自己用 `verify_claim` 判，那就顺便确认这条判据能直接翻译成 `judge` + `predicate`；
   翻不过去，说明它还没写清楚，别派。
2. **算法与规模**——什么算法、上界多少、复杂度估计。
3. **反证条件**——什么样的输出算推翻判据，什么样算"无结论"，什么样算"算不动"。**这一条最容易被漏**，漏了就会把"没搜到"当成"不存在"。
4. **交付物**——脚本落盘路径 + 关键输出 + 一句结论。明确要求它不要回贴中间日志。

**计算工具要写死，不要给选项。** 这条是有代价换来的：曾经有任务书写成"用 `viz_python` 或 `browser` 的 eval"，成员挑了 `browser`，而那个环境浏览器没开，它查了一次状态就放弃了，一个数字都没算出来。现在 `browser` 根本不在成员的白名单里——这就是白名单比黑名单强的地方：它会选错，是因为你给了它选项。

`viz_python` 的语义是**执行器**，不是画图工具：`print` 什么就回什么，返回值里的 `stdout` 就是结果，没有图也算跑成功（`ok: true`, `has_figure: false`）。所以不要为了"让它算"而在末尾补一句 `plt.plot()` 去骗一次保存——那只会把数字埋进 PNG 里，复核时还得再解一次图。纯算就只 print；要图才画图。

探索级再加一条：**写明预算和停止条件**。没有停止条件的搜索不算实验，算消耗——它会一直跑到超时，然后你得到一个没有信息量的"没找到"。

顺带说清楚：**组队不是免检通道**。判据没写出来就去派批量计算，一样会被拦——因为那时候你写不出任务书，成员只能瞎搜，带回来的数字你不知道该怎么用。

## 三个数，每队跑完必看

队伍会不会退化成"队长一个人干、其余人陪跑"，不靠自觉，靠量。跑完一次就量这三个：

| 指标 | 怎么算 | 红线 |
|---|---|---|
| **塌陷** | 先剔除"等待"（只调 `agent_teams_status` 的 step），再看两个结构：队长占调整后总产出的比例；最大成员占**成员总产出**的比例 | 队长 > 80% 且成员总量不如队长一个人 → 独干；成员最大 > 80%（≥3 人）→ 只剩一个在干 |
| **交接** | 任务书+回报的 token 占总 token 的比例 | > 30%，说明你在把推导塞进任务书 |
| **判定覆盖** | 报告里引用的断言数 ÷ `claims.jsonl` 里有记录的条数 | < 1，说明有断言没被判定就写进了报告 |
| **判据冲突** | `claim_audit` 返回的 `conflicts`，以及 `verdict_flipped` | > 0，说明判定之后断言/脚本/规则被改过，或结论翻过面 |
| **回收** | 派出去的任务里，报告写明处置的比例 | < 1，说明有成员的产出被整份丢掉 |
| **自审** | 台账非空时 `claim_audit` 的调用次数 | = 0，说明"判据没被改过"这句话没有任何工具支撑 |

前两个数说的是分工，后面几个说的是**结论可不可信**。分工再好而判定覆盖不到 1，那一轮就是没验；
覆盖到 1 却一次没自审，那一轮是"自己说验过了"。

关于塌陷有个实测教训，别按直觉改这个指标：**"队长占 48.7%"不等于塌陷**。team4 那一轮剔除等待后只降到 46.1%，
因为队长确实自己在啃模型（581k 字符推理）。老版本用"任一成员 > 60%"一条阈值，把"队长想得多"和"队长把活全干了"
混成了一件事，于是把一个正常的轮次报成病态。等待本身只占 9.8%——它值得单列，但不值得为它改结论。

另外，剔除协调调用**只剔 `status`**。不要连 `update_task` / `send_message` 一起剔：成员的结论就写在
`update_task` 的 output 参数里，那一整个 step 只调这一个工具，剔掉等于把成员最重的那段工作判成等待，
队长占比会被虚构地抬高（实测 42.7% → 59.3%），比原指标错得更远。

**不要轮询 `status` 等成员。** agent-teams 没有阻塞等待工具，但成员回执会以 `agent/inbox/spliced` 唤醒你：
交完任务就结束回合，比每 20 秒问一次"完了吗"省得多——轮询花的不是时间，是每一轮都要重建一次"该等还是该收"的推理。

塌陷的机制和混合专家模型里的路由塌陷一模一样：没有显式的均衡压力，任务会自发涌向最强的那一个，其余成员逐渐退化成装饰。**这时候该改的是路由和任务切分，不是成员的能力。**

交接成本高则几乎总是同一个原因：你把"我是怎么想到的"写进了任务书。任务书只需要 claim 和判据——写推导既贵，又污染 `check` 的独立性。

`team-metrics.mjs` 会从会话日志里直接算这三个数，不要手估。

如果这个环境**连组队工具都没有**，批量计算会降级为你自己跑。这时候必须做一件事：**限制输出体积**。只打印统计量、极值、命中列表，绝不逐条打印。否则几千行日志会把上下文吃掉，你会得到一个"跑完了但想不动了"的局面——那比没跑更糟。

## 换问题要重开一张票

verify 解锁的是**这一个问题**，不是整个会话。第一个子问题走完了流程，不代表第二个子问题也可以直接开算——同一位作者的同一篇论文，能回答 A 问题，不代表能回答 B 问题。

所以子问题一变，就开新票（`research_stage(action=open, question=...)`），回到 survey。上一张票的 `prior_art` 不继承。

这条规则防的是最隐蔽的一种退化：**流程走了一遍，然后永远躺在终点。**

## 第一步 survey：把别人的天花板摸清楚

这一步的唯一产出是一句话能回答的四个问题，缺一个都不算读完：

1. **谁做过**——不是"某某研究过这个问题"，而是具体到篇：作者、年份、做到哪一版。
2. **化成了什么**——他把几何/物理/组合的问题，等价成了什么代数对象？椭圆曲线？四次曲面？Pell 族？某个簇上的有理点？**这一步最关键**：不同化法决定了后面所有技术能不能用。
3. **用了什么手段**——降维、消元、纤维化、模形式、筛法、递降。要具体到"他消掉了哪个变量""他在哪个曲面上做纤维化"。
4. **卡在哪一步**——这是全篇最值钱的一句话。是"技术上算不动"，还是"这条路原理上封死"？前者可能换工具就能过，后者必须换路。

**禁止**在这一步写"综合来看，该问题仍未解决"——那是摘要，不是理解。

**每条"谁做过"后面必须跟一条原文引文，格式写死：**

    [refs/berry1990.txt] “原文里连续存在的一句话”

门禁会打开那个文件、把句子按空白归一化后做子串检索；检索不到就拒绝推进。句子可以截取，**不能改写、不能拼接、不能翻译**（翻译过的引文等于没引）。至少两条，来自不同文献。

理由是这条规则只防一种情况：**"我知道"冒充"我读到"**。模型知道 Berry 写过三距离问题，这句话大概率是对的——但它证明不了手上这篇读没读，而"卡在哪一步"恰恰只有读了才知道。字数门槛防不住这个，一个熟悉领域的人凭记忆就能写满 400 字。

数据来源优先级：本地已有的全文（PDF 抽出的 txt）> 开放获取的预印本/仓储 > 摘要与评论（zbMATH review 常有高质量的"这篇文章做了什么、没做什么"）> 二手转引。**二手转引必须标注，不能当读过。**

## 第二步 synthesis：把障碍变成一个可判真假的命题

这一步把第一步的第 4 问答"翻译"成一个判据：

- 差的形式：*"可以用计算机搜索更大范围看看"*
- 好的形式：*"如果 S₄ 上存在有理点，那么它在某个除子上的像必须落在某个子群里；这一点可以用 2-下降检验，而且检验结果是可判定的"*

判据必须满足三条：

1. **可判真假**——存在一个明确的、有限的计算或证明能给出"是/否"。
2. **有来源**——它接在第一步发现的某个具体障碍上，不是凭空想的。
3. **可被推翻**——写清楚"什么样的结果会证明我这个思路是错的"。写不出第三条的判据，通常是伪装成判据的愿望。

## 第三步 verify：才算

到这一步才算，而且只算第二步写下的判据。规矩：

- 计算前先写下**预期**。跑完对不上，先怀疑自己的推导，再怀疑结果。
- 报告必须给出：算法、界、复杂度、真实输出、以及"这个界相对于文献已有的搜索处于什么位置"。**如果文献已经搜到 10^6 而你只到 10^5，这不算结果，算复现。**
- 数值结果只用来**检验或推翻**判据，不用来"发现"判据。发现的活是前两步干的。

## 交付时的三栏标注

每条陈述必须标清来源，不许混：

- `[文献已知]`——出自哪篇，可核。
- `[我算出的]`——给出脚本和输出，别人能复现。
- `[scratch]`——草稿级验算，只说明自己看懂了，不构成本研究的证据。
- `[推测]`——没有依据的直觉，明说是直觉。

混在一起写，读者（和模型自己）就无法分辨哪些站得住。**一段没有标注的"综合判断"，通常是把推测包装成了结论。**

尤其要注意把 `[scratch]` 混进 `[我算出的]`：前者是"我核对了别人说的数"，后者是"我发现了新东西"，分量差着一个数量级。

## 可以退回去

读到新证据发现判据站不住，就退回 survey 重来，这是正常研究动作，不是失败。回退会清空 `prior_art` 与 `plan`——因为读到新东西之后，旧的综述已经不完整了。**退回去再立刻推回来，等于什么都没做。**

## 走不通怎么办

走不通是有价值的结果，前提是说清楚**死在哪一步、被什么挡住**：

- 差的形式：*"该方向仍需进一步研究"*
- 好的形式：*"卡在第 3 步：需要的模形式层级超出当前可计算范围；除非能证明某个 L-函数的特殊值非零，否则这个下降做不下去"*

写清楚死因，下一个人才不用重新死一次。

而且**要落成记录**，不能只写在报告里——报告会被压缩成交接摘要，死因第一个被压掉。用 `research_note` 的 `dead_end` 类型写，`blocked_at` 填第几步，`needs` 填"要过这一关还需要什么"。下一轮的任务书会自动带上它。

## 记忆只存意图，不存实现

这条是拿一次真实崩坏换来的：有个队长在组队前反复纠结 "per user's memory: 必须建队、加成员（`tool_policy=computer`）"，
然后开始猜 `computer` 这个 policy id 存不存在。它当然不存在——那个 id 来自更早的一套分工体系，
在撤掉旧角色、重划三角色之后就没清理过。**如果它真按记忆填了，成员会因未知 policy 启动失败，
而失败现场看起来像模型自己不会组队。**

所以规矩是：

- **可以记**：意图（"计算派给成员，不要队长自己算"、"读文献不是 draft 的活"）。
- **不许记**：实现细节（policy id、工具名、路径、文件行号、"配置长这样"）。
  这些写在配置里和 skill 里，已经有两处了；记忆是第三处，而它不会随配置更新。

判据很简单：**一句话如果在配置改了之后会变成假前提，它就不该进记忆。**
"成员要用 `tool_policy=computer`" 会过期；"计算不要队长自己干" 不会。

发现记忆里有过期条目时，主动清掉并说一声。不要等它把下一次组队搞崩才回头找。
